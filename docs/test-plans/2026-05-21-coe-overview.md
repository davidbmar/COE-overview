# COE Overview — Human Test Plan

Generated by the test-analyst after the final code review for the 2026-05-21
COE Overview implementation. The automated suite (160 tests passing in ~2s)
covers every acceptance criterion AC1.1 through AC4.4. This plan covers the
operational verifications (AC5/AC6/AC7) and the closed-loop end-to-end checks
that the automated suite cannot exercise on its own.

## Prerequisites

- Project root: `/Users/dmar/src/COE-overview`
- Local Postgres running: `podman compose up -d postgres` (already running as
  `coe-postgres` on `localhost:5432`)
- Alembic migrations applied: `uv run alembic upgrade head`
- `uv sync` succeeds
- `uv run pytest` passes (160 tests, ~2s)
- `uv run ruff check` and `uv run mypy coe tests` both clean
- `.env` populated with real (or sandbox) credentials for Jira, Wiz,
  CrowdStrike, Vibranium, HR, `GOOGLE_DRIVE_FOLDER_ID`, and
  `GOOGLE_SERVICE_ACCOUNT_FILE` pointing to a service account JSON
- For Phase 7: Docker (or Podman) and `kubectl` available with cluster
  context configured; Grafana 13+ instance reachable

## End-to-End: First Production Monday (Closed-Loop)

Validates that one full week of source updates flows from each system → COE doc
and that manual updates from the previous week are picked up.

1. **Friday before**: in Jira / Wiz / CrowdStrike / Vibranium, ensure at least
   one issue per source has been updated (status changed, assignee changed,
   severity changed) since the prior Monday's run.
2. **Monday morning at scheduled time**: confirm the CronJob fires
   (`kubectl get jobs -l app=coe-overview -n coe`).
3. After the job completes, open the Doc URL from the new `coe_runs` row.
4. In each "Changed events" section, locate the records you modified Friday.
   Each should appear with its updated state.
5. Cross-reference the owner/manager columns in the doc against current HR data
   — confirm no `(missing owner)` rows for owners that legitimately exist.
6. **Confirm doc lands in the right Drive folder**: in the Drive UI, navigate
   to the folder pointed at by `GOOGLE_DRIVE_FOLDER_ID`; confirm the new doc
   is there and shared with the COE attendees.
7. During the actual meeting, gather feedback on doc structure / panel signal.
   Open issues for next-week iteration.

## End-to-End: Partial-Failure Production Behavior (AC3.4 live verification)

1. In the cluster, edit the secret backing one source (e.g., Wiz) and set the
   token to an invalid value: `kubectl edit secret coe-secrets -n coe`.
2. Manually trigger the CronJob (step 7.6 above).
3. After completion, in psql: `SELECT status, errors_json FROM coe_runs ORDER BY id DESC LIMIT 1;`
   — confirm `status='partial'` and `errors_json->'wiz'->>'error'` contains an
   `AuthError` message.
4. Confirm other sources still ingested: `SELECT source, COUNT(*) FROM coe_events WHERE last_seen_at >= (SELECT started_at FROM coe_runs ORDER BY id DESC LIMIT 1) GROUP BY source;`
   — non-Wiz sources show fresh rows.
5. Open the rendered Doc — confirm Wiz section is empty or shows last-week's
   stale data; other sources show fresh data.
6. In Grafana, view the per-source ingest panel — Wiz shows the gap; others healthy.
7. Restore the correct Wiz token; trigger again; confirm `status='ok'` and Wiz
   data flows back.
